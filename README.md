# ASM OS — ASM Industries lightweight engineering workstation

A bootable, hybrid BIOS + UEFI live ISO built from **Debian 13 (trixie)** with **Xorg + Openbox + tint2 + LightDM**,
aimed at 1–2 core x86_64 PCs with 1–1.5 GB RAM. Everything is generated by one script: `sudo ./build.sh`.

> **Status:** the scripts were syntax-checked, the XML configs validated, the branding generator and the
> package/overlay logic exercised, but a full `debootstrap` build and a boot test were **not** possible in the
> environment where this was written (no network, no loop devices). Treat the first build as a shake-down:
> the build fails early and readably if a package name differs on your mirror (see *Troubleshooting*).
> The RAM numbers below are design targets to **verify with `asm-sysinfo`**, not measurements.

---

## 1. Architecture blueprint

| Layer | Choice | Why |
|---|---|---|
| Base | Debian stable, `debootstrap --variant=minbase`, `--no-install-recommends` everywhere | Best driver/firmware coverage for legacy hardware; glibc runs vendor toolchains (Arduino cores, avr-gcc, OpenOCD scripts) unmodified; KiCad, TShark, Falkon, OpenOCD, avrdude are all packaged and security-patched. |
| Why not Alpine | Alpine typically idles a few tens of MB lower (musl, OpenRC), but… | musl breaks many prebuilt embedded toolchains; no easy non-free firmware for old Wi-Fi/GPU; its RAM-resident "diskless" mode would eat a 1 GB machine. Debian's extra footprint is largely recovered by the tweaks below. |
| Kernel | Debian `linux-image-amd64` (mainline LTS 6.12) | Generic, modular, zram + zstd built in. 64-bit CPUs only (excludes 32-bit-only parts such as the Pentium M or the first Atom netbooks). |
| Live system | `live-boot` + `live-config`, squashfs (zstd) | Boots from USB/DVD, creates the user `asm` at every boot, optional persistence. |
| Display | Xorg (modesetting / fbdev / vesa fallbacks) | No Wayland compositor overhead; works on anything. |
| Desktop | Openbox + tint2 + feh, **no compositor**, no file indexer, no desktop environment daemons | ~25 MB for WM + panel. |
| Login | LightDM, autologin → Openbox | Straight to the desktop. |
| Boot menu | ISOLINUX (BIOS) + standalone GRUB (UEFI), branded background | One ISO, both firmware types. |
| Splash | Plymouth `script` theme (`WITH_PLYMOUTH=0` to drop it) | Branded boot; zero resident cost after boot. |

### Memory-saving measures
* **ZRAM swap** (`asm-zram.service`): zstd-compressed, sized at 100 % of RAM (≈2–3× effective), priority 100.
* **sysctl**: `swappiness=150`, `page-cluster=0`, tuned dirty ratios, NMI watchdog off.
* **earlyoom**: kills the largest process before a 1 GB box freezes.
* **No heavy daemons**: no cups, avahi, bluetooth, ModemManager, rsyslog, snapd, PackageKit; apt/man-db/e2scrub timers masked; `NetworkManager-wait-online` and sshd disabled.
* **journald volatile**, 16 MB cap; systemd memory/tasks accounting off.
* **No compositor**, no GTK animations, Openbox doesn't redraw windows while resizing.
* **Browser**: Falkon launched through `asm-browser` with `--renderer-process-limit=2 --disable-gpu --enable-low-end-device-mode` etc.
* **Slim image**: docs/man/locales (except en) excluded via dpkg (license files kept; `KEEP_DOCS=1` to disable).
* Expected idle after login ≈ **170–250 MB in use** (design target; Xorg ≈ 50 MB, NetworkManager + applet ≈ 40 MB, panel + WM ≈ 25 MB). A running Qt-WebEngine browser will dominate everything else.

## 2. Build

Host: Debian 12/13 or Ubuntu 22.04/24.04 (x86_64), root, ~10 GB free disk, internet. A Debian container/VM is the safest host.

```bash
tar xzf asm-os.tar.gz && cd asm-os
sudo ./build.sh                       # rootfs + ISO  -> out/ASM-OS.iso (+ .sha256)
```
Missing host tools (`debootstrap`, `xorriso`, `squashfs-tools`, `grub-efi-amd64-bin`, `isolinux`, `mtools`, `imagemagick` …) are installed automatically.

Other commands: `sudo ./build.sh rootfs | iso | shell | clean`.
`iso` re-packs an existing rootfs (minutes), `shell` opens a chroot to experiment.

### Build options (environment variables)
| Variable | Default | Effect |
|---|---|---|
| `SUITE` | `trixie` | Debian release (`bookworm` works too) |
| `BROWSER_PKG` | `falkon` | `chromium`, `netsurf-gtk` (tiny, weak JS), `epiphany-browser` |
| `WITH_KICAD` | `0` | `1` = full KiCad (no 3-D models). Heavy: use with ≥1.5 GB RAM; default ships `gerbv` Gerber viewer instead |
| `WITH_FIRMWARE` | `1` | Wi-Fi / GPU / microcode blobs from `non-free-firmware` |
| `WITH_PLYMOUTH` | `1` | Graphical boot splash |
| `WITH_WIRESHARK` | `0` | Wireshark Qt GUI (TShark always included) |
| `WITH_ARM` | `0` | `arm-none-eabi` GCC toolchain |
| `SQUASHFS_COMP` | `zstd` | `xz` for a smaller ISO, slower boot on old CPUs |
| `ASM_VERSION`, `ASM_HOME_URL`, `MIRROR` | see `build.sh` | Branding / mirror |
| `ARDUINO_CLI_SHA256` | empty | Pin a checksum for the downloaded Arduino CLI |

Example: `sudo WITH_KICAD=1 WITH_WIRESHARK=1 SQUASHFS_COMP=xz ./build.sh`

Typical numbers (estimates): 25–45 min first build, ISO ≈ 0.7–1.0 GB (≈ 0.6 GB without firmware).

## 3. Testing

### QEMU (1 core, 1 GB)
```bash
sudo apt install qemu-system-x86 ovmf
./test/run-qemu.sh                            # BIOS, 1 CPU, 1024 MB, KVM if available
FIRMWARE=uefi ./test/run-qemu.sh              # UEFI path (needs ovmf)
RAM_MB=1536 CPUS=2 ./test/run-qemu.sh         # top of the target range
ACCEL=tcg CPU_MODEL=Penryn ./test/run-qemu.sh # pure emulation = deliberately slow "old PC"
```
The raw command behind it:
```bash
qemu-system-x86_64 -enable-kvm -cpu host -smp cpus=1,cores=1,threads=1 -m 1024 \
  -cdrom out/ASM-OS.iso -boot d -vga std -nic user,model=e1000 -usb -device usb-tablet
```
Throttle further on the host: `systemd-run --user --scope -p CPUQuota=50% ./test/run-qemu.sh`

### VirtualBox
```bash
./test/virtualbox.sh                          # 1 vCPU, 1024 MB
FIRMWARE=efi ./test/virtualbox.sh             # UEFI
RAM_MB=1536 CPUS=2 CPU_CAP=50 ./test/virtualbox.sh
```
(equivalent to `VBoxManage createvm … modifyvm --memory 1024 --cpus 1 --cpuexecutioncap 100 --ioapic on …`; see the script.)

### What to check
1. Boot menu shows the ASM branding (BIOS and UEFI); desktop appears without a login prompt.
2. Open a terminal → `asm-sysinfo`: "In use" should be **< 250 MB**; zram line shows `/dev/zram0`.
3. Panel: menu button, launchers, tray with the network applet; right-click desktop → ASM menu.
4. `tshark -D`, `nmap --version`, `python3 --version`, `gcc --version`, `arduino-cli version`, `avrdude -?`, `openocd --version`.
5. `systemd-analyze` for boot time; `systemctl list-units --state=failed` should be empty.

### Real hardware
```bash
sudo dd if=out/ASM-OS.iso of=/dev/sdX bs=4M status=progress conv=fsync   # triple-check sdX!
```
Disable Secure Boot (the bundled GRUB is unsigned). Use "Safe graphics" in the boot menu if the screen stays black.

## 4. Using it

* Login (auto): user **`asm`**, password **`live`**, passwordless `sudo`. **Change this before shipping** (`LIVE_*` in `overlay/etc/live/config.conf.d/asm-os.conf` and `live-config.*` in `KERNEL_CMDLINE`, then keep `autologin-user` in `overlay/etc/lightdm/lightdm.conf.d/50-asm-os.conf` in sync).
* `asm` is in `dialout` (serial), `plugdev` (USB programmers), `wireshark` (capture), `netdev`, `sudo`.
* `sshd` is installed but **off**: `sudo systemctl enable --now ssh` (host keys are regenerated each live boot).
* Arduino: `arduino-cli core update-index && arduino-cli core install arduino:avr` (needs internet once). `gcc-avr`/`avrdude` work offline.
* Shortcuts: `Super+Space` menu · `Super+Enter` terminal · `Super+B` browser · `Super+E` files · `Super+G` Geany · `Super+L` lock · `Super+←/→` half-tile · `Alt+Tab` · `Ctrl+Alt+Del` htop.
* **Persistence on USB** (optional): add an ext4 partition labelled `persistence` containing a file `persistence.conf` with the single line `/ union`, and boot with the extra kernel parameter `persistence`.
* **Installing to disk** is not included (live system only). A small `asm-install` script (unsquashfs + grub-install) or Calamares can be added as a next stage.
* Live mode keeps all writes in RAM; avoid `toram` on 1 GB machines (it copies the whole image into memory).

## 5. File map (what to edit for what)

| Goal | File |
|---|---|
| Add/remove software | `packages.list` |
| Distro identity, services, cleanup | `chroot/setup.sh` |
| Wallpaper / splash / logo colours & text | `tools/gen-branding.sh` |
| Boot menu text, kernel parameters | `boot/*.cfg.in`, `KERNEL_CMDLINE` in `build.sh` |
| Desktop menu / hotkeys | `overlay/etc/skel/.config/openbox/{menu,rc}.xml` |
| Panel layout | `overlay/etc/skel/.config/tint2/tint2rc` |
| Window theme | `overlay/usr/share/themes/ASM-Dark/openbox-3/themerc` |
| Session startup | `overlay/etc/skel/.config/openbox/autostart` |
| GTK/Qt dark look | `overlay/etc/gtk-3.0/settings.ini`, `overlay/etc/skel/.config/qt6ct/` |
| zram / sysctl / OOM | `overlay/etc/default/asm-zram`, `overlay/etc/sysctl.d/`, `overlay/etc/default/earlyoom` |
| Boot splash | `overlay/usr/share/plymouth/themes/asm/` |

Anything under `overlay/` is copied verbatim into the image after package installation.

## 6. Troubleshooting

* **"Required packages not found…"** – package names drift between releases. Edit `packages.list` (add `?` to make a package optional) and re-run; the rootfs is reused.
* **`debootstrap: No such script … trixie`** – handled automatically (linked to `sid`); upgrade debootstrap if it still fails.
* **Keyring / signature errors for trixie on an older host** – update `debian-archive-keyring`, or build inside a Debian 13 container.
* **Black screen after the menu** – boot "Safe graphics"; add `nomodeset` permanently in `KERNEL_CMDLINE` if the hardware needs it.
* **No Wi-Fi** – keep `WITH_FIRMWARE=1`; identify the chip with `lspci -nn` / `lsusb` and add the matching `firmware-*` package.
* **Qt apps look light-themed** – `qt6ct` is optional in `packages.list`; if its package or colour file is missing, edit `overlay/etc/skel/.config/qt6ct/qt6ct.conf`.
* **Inspect a failed build** – `sudo ./build.sh shell`.
